# LaTeX math, stage 2: display layout on one box engine — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `$$\frac{-b \pm \sqrt{b^2-4ac}}{2a}$$` draws as four centred rows of box art in
the document, and `$E = mc^2$` still draws as `E = mc²` on the line — both out of one
engine.

**Architecture:** A box tree replaces stage 1's direct event→string walk. `boxes.rs` holds
the box model of spec §4 (`width`, `above`, `below`) and its composition arithmetic;
`build.rs` turns a `pulldown-latex` event stream into that tree and is the only place that
consults `Mode`; `draw.rs` renders the tree, to a `Canvas` for display and to one `String`
for inline. Inline is not a second code path — it is the same tree under the constraint
`above == 0 && below == 0`, and a node that cannot meet it either rewrites itself (a
fraction becomes `a/b`) or fails with `MathError::NotInline`. `src/math/inline.rs` is
deleted.

**Tech Stack:** Rust 2024, `pulldown-latex` 0.8.0, `comrak` 0.54, `insta` snapshots,
`proptest`.

**Spec:** `docs/superpowers/specs/2026-08-19-math-design.md` — read it first, and read §4
before anything else in this plan. Every task below cites the section it implements. Where
this plan makes a decision the spec does not, it says so in a **Decision** note and gives
the reasoning; those are the places to push back.

**Predecessor:** `docs/superpowers/plans/2026-08-19-math-stage-1.md`, whose "Notes for
stage 2" section (line 3156) is folded into the tasks below rather than left to be
rediscovered.

## Global Constraints

Every task's requirements implicitly include this section.

- **No C toolchain, ever.** No new dependency in this stage. `pulldown-latex`'s only
  optional feature is `regex` and it stays off. A C compiler in the build breaks the
  static musl release.
- **Rust edition 2024**; the crate forbids `unsafe`. Nothing here needs it.
- **Comments, identifiers and documentation in English.**
- **Never run cargo with more than 4 jobs.** Every command below is written `-j4`. Do not
  drop it — the machine is shared with other people's work.
- **`cargo test -j4`, never `cargo test -j4 --all-targets`.** `--all-targets` silently
  skips doctests and still reports success. `--all-targets` belongs on `cargo clippy` and
  nowhere else.
- **`crate::text` is the single home of width logic** (`src/text/mod.rs:4-7`). Anything
  counting display columns — implementation or test — goes through `text::display_width`
  or `text::grapheme_width`, never `unicode_width` directly.
- **Every renderer returns a canvas that is exactly `width` columns on every row.**
  `Canvas::check_invariants()` is the assertion; call it in every test that builds one.
- **Nothing about math may panic.** Every entry point returns `Result`. The proptest at
  `src/math/tests.rs:258-286` already covers arbitrary input and LaTeX-shaped noise through
  `render_inline`; it must keep passing at every task. Task 9 adds the matching one for
  `render_display`, which spec §14 requires and which no existing test covers.
- **`src/math/` is a sibling of `src/mermaid/`, not a leaf.** It may use `crate::error`,
  `crate::text`, `crate::canvas` and `crate::theme` — spec §8 gives it
  `render_math(src, width, &Theme, Mode) -> Result<Canvas, MathError>`, which is the shape
  `crate::mermaid::render_mermaid_with` already has (`src/render/bridge.rs:7`). It must
  know nothing of `render`, `tui` or `doc`; stage 1's final review verified that and Task 4
  is the one that could break it.
- **Every claim about what a function or crate does needs a `file:line`.** Stage 1's plan
  asserted seven such things without one; three reached the source, and the worst rendered
  `\left(\frac{a}{b}\right)^2` as `a/b²` — wrong mathematics, silently. If a step tells you
  something about the tree and you cannot find it at the cited line, **stop and report it**
  rather than working around it.
- **Render the binary.** Four stage-1 defects were invisible to a fully green suite and
  were found only by running `mdmost` and looking. Every task that changes what a reader
  sees ends with a step that runs it.
- **A new module lands dead and clippy is `-D warnings`.** `boxes.rs`, `spacing.rs` and
  `build.rs` each have no caller outside their own tests until the task after them, so
  clippy fails the gate with `never used` on every item. The suppression is
  `#![allow(dead_code)]` with a comment saying when it comes out -- **not** `#![expect(...)]`,
  which fires `unfulfilled_lint_expectations` because the test target sees the surface live
  while the lib target does not (measured on Task 1). **Task 3 removes `boxes.rs`'s allow
  when `build.rs` starts calling it; Task 4 removes `spacing.rs`'s and `build.rs`'s.**
  A stale `allow(dead_code)` hides the next real dead item, so removing it is part of the
  definition of done, not a tidy-up.
- **Commit after every task**, with the message given in the task's final step. Backticks
  in `git commit -m` are command-substituted by the shell — every commit step below writes
  the message to a file and uses `git commit -F`.

## Task ordering and why

Tasks 1–5 build the engine with no user-visible change at all: the tree, the spacing table,
the builder, the drawer and the inline rewrites, each testable in isolation. **Task 6 is the
risky one** — it re-points `render_inline` at the new engine and deletes the old walk, and
stage 1's 1407 tests are the gate. It is deliberately early: a regression there is cheapest
to find before nine more tasks are stacked on top, and everything after it is addition
rather than replacement.

Tasks 7–8 add the remaining two-dimensional constructs. Tasks 9–12 place the result in the
document and make it selectable. Tasks 13–15 are theme, macros and documentation.

### Task 1: The box model

Spec §4. Three numbers per box and the arithmetic that composes them. No parsing, no
drawing, no `pulldown-latex` import — this file is pure geometry and is where every later
task's layout bug will be diagnosed, so it is tested to death first.

**Files:**
- Create: `src/math/boxes.rs`
- Modify: `src/math/mod.rs` (add `mod boxes;`)
- Test: `src/math/boxes.rs` (a `#[cfg(test)] mod tests` at the foot, as `src/math/scripts.rs:146` does)

**Interfaces:**
- Consumes: `crate::text::display_width` (`src/text/mod.rs`).
- Produces: `MathBox`, `BoxContent`, and the constructors `text`, `row`, `fraction`,
  `scripts`, `limits`, `radical`, `fenced`. Tasks 3–11 build trees out of exactly these;
  no later task adds a constructor without adding its arithmetic here first.

**Decision — the type is `MathBox`, not `Box`.** `Box` is in the Rust prelude. A local
type shadowing it inside a module that also needs `Box<[ArrayColumn]>` from
`pulldown_latex::event::Grouping::Array` (Task 11) reads as a trap. `MathBox` costs six
characters and removes the question.

**Decision — `width`, `above` and `below` are `u16`.** The canvas is `u16`-wide
(`Canvas::new(width: u16, …)`, `src/canvas/mod.rs:327`) and every arithmetic below is
saturating, so an absurd formula produces a clamped box rather than a panic. The crate
forbids panics in `src/math/`, so **every `+` in this file is `saturating_add`**.

```rust
// SPDX-License-Identifier: MIT
//! The box model of design spec §4.
//!
//! Three numbers describe every box, all in terminal cells: `width` in display columns,
//! and `above` / `below` as the rows either side of the baseline. The baseline is the row
//! the surrounding text sits on, which is what lets an inline formula share a row with
//! prose: a box with `above == 0 && below == 0` fits on that row and nothing else does.
//!
//! Composition is arithmetic, and it is all here rather than spread through the builder,
//! because a layout defect shows up as a wrong number long before it shows up as wrong
//! box art. `build.rs` decides *what* to compose; this file decides how big the result is.
//!
//! Every addition saturates. `src/math/` may not panic (design spec §9) and a formula is
//! attacker-supplied text, so a pathological nesting depth has to clamp rather than
//! overflow. A clamped box draws wrongly and is caught by the caller's width check; an
//! overflow aborts the pager.

use crate::text::display_width;

/// A laid-out formula fragment: how much space it takes, and what is in it.
#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) struct MathBox {
    /// Display columns.
    pub(crate) width: u16,
    /// Rows above the baseline.
    pub(crate) above: u16,
    /// Rows below the baseline.
    pub(crate) below: u16,
    /// What is drawn.
    pub(crate) content: BoxContent,
}

/// What a [`MathBox`] draws, once [`MathBox`] has said how big it is.
#[derive(Debug, Clone, PartialEq, Eq)]
pub(crate) enum BoxContent {
    /// One row of already-resolved cells.
    Text(String),
    /// A horizontal list sharing one baseline.
    Row(Vec<MathBox>),
    /// Numerator over denominator. The rule row is the baseline.
    Fraction {
        /// Drawn above the rule.
        num: std::boxed::Box<MathBox>,
        /// Drawn below it.
        den: std::boxed::Box<MathBox>,
    },
    /// A base with scripts set to its right.
    Scripts {
        /// What is being scripted.
        base: std::boxed::Box<MathBox>,
        /// Below-right, if any.
        sub: Option<std::boxed::Box<MathBox>>,
        /// Above-right, if any.
        sup: Option<std::boxed::Box<MathBox>>,
    },
    /// A base with its scripts stacked over and under it.
    Limits {
        /// The operator, which keeps the baseline.
        base: std::boxed::Box<MathBox>,
        /// Stacked below.
        under: Option<std::boxed::Box<MathBox>>,
        /// Stacked above.
        over: Option<std::boxed::Box<MathBox>>,
    },
    /// A radical: a stroke, an overline, and what is under them.
    Radical {
        /// What the root is taken of.
        radicand: std::boxed::Box<MathBox>,
        /// The index of the root, as in a cube root.
        index: Option<std::boxed::Box<MathBox>>,
    },
    /// A body wrapped in delimiters sized to it.
    Fenced {
        /// The opening delimiter, absent for `\left.`.
        left: Option<char>,
        /// The closing delimiter, absent for `\right.`.
        right: Option<char>,
        /// What is enclosed.
        body: std::boxed::Box<MathBox>,
    },
}

impl MathBox {
    /// Total rows: everything above the baseline, the baseline, everything below.
    pub(crate) const fn height(&self) -> u16 {
        self.above.saturating_add(1).saturating_add(self.below)
    }

    /// Whether this box fits on the row the surrounding prose sits on.
    ///
    /// This is the whole of design spec §4's inline constraint. `build.rs` is the only
    /// caller that acts on it, and it does so by rewriting the box rather than by
    /// handing the formula to different code.
    pub(crate) const fn is_inline(&self) -> bool {
        self.above == 0 && self.below == 0
    }

    /// Whether this box draws no cells at all.
    ///
    /// Design spec §16.3: a display block whose layout produces nothing contributes no
    /// rows to the document — no frame, no caption, no blank line.
    pub(crate) fn is_empty(&self) -> bool {
        self.width == 0 && self.above == 0 && self.below == 0
    }
}

/// One row of cells, measured as the terminal will draw it.
pub(crate) fn text(s: impl Into<String>) -> MathBox {
    let s = s.into();
    MathBox {
        width: u16::try_from(display_width(&s)).unwrap_or(u16::MAX),
        above: 0,
        below: 0,
        content: BoxContent::Text(s),
    }
}

/// A horizontal list: widths add, and each side of the baseline takes the tallest part.
pub(crate) fn row(parts: Vec<MathBox>) -> MathBox {
    let mut width = 0u16;
    let mut above = 0u16;
    let mut below = 0u16;
    for part in &parts {
        width = width.saturating_add(part.width);
        above = above.max(part.above);
        below = below.max(part.below);
    }
    MathBox {
        width,
        above,
        below,
        content: BoxContent::Row(parts),
    }
}

/// Numerator over denominator, the rule spanning the wider part (design spec §6.1).
///
/// The rule row *is* the baseline, so the numerator is entirely above and the denominator
/// entirely below — each contributing its whole height, not just its `above`.
pub(crate) fn fraction(num: MathBox, den: MathBox) -> MathBox {
    let width = num.width.max(den.width);
    let above = num.height();
    let below = den.height();
    MathBox {
        width,
        above,
        below,
        content: BoxContent::Fraction {
            num: std::boxed::Box::new(num),
            den: std::boxed::Box::new(den),
        },
    }
}

/// A base with scripts to its right (design spec §4, `ScriptPosition::Right`).
///
/// The superscript's lowest row sits one above the base's baseline and the subscript's
/// highest row one below it, so a script occupies exactly its own height above or below
/// the baseline -- the "one above" is where its lowest row lands, not extra clearance.
pub(crate) fn scripts(base: MathBox, sub: Option<MathBox>, sup: Option<MathBox>) -> MathBox {
    let script_width = sub
        .as_ref()
        .map_or(0, |b| b.width)
        .max(sup.as_ref().map_or(0, |b| b.width));
    let above = base
        .above
        .max(sup.as_ref().map_or(0, |b| b.height()));
    let below = base
        .below
        .max(sub.as_ref().map_or(0, |b| b.height()));
    MathBox {
        width: base.width.saturating_add(script_width),
        above,
        below,
        content: BoxContent::Scripts {
            base: std::boxed::Box::new(base),
            sub: sub.map(std::boxed::Box::new),
            sup: sup.map(std::boxed::Box::new),
        },
    }
}

/// A base with its scripts stacked over and under it (design spec §6.3).
///
/// The operator keeps the baseline, so a `\sum` stays on the reader's line and its limits
/// grow the block around it.
pub(crate) fn limits(base: MathBox, under: Option<MathBox>, over: Option<MathBox>) -> MathBox {
    let width = base
        .width
        .max(under.as_ref().map_or(0, |b| b.width))
        .max(over.as_ref().map_or(0, |b| b.width));
    let above = base
        .above
        .saturating_add(over.as_ref().map_or(0, |b| b.height()));
    let below = base
        .below
        .saturating_add(under.as_ref().map_or(0, |b| b.height()));
    MathBox {
        width,
        above,
        below,
        content: BoxContent::Limits {
            base: std::boxed::Box::new(base),
            under: under.map(std::boxed::Box::new),
            over: over.map(std::boxed::Box::new),
        },
    }
}

/// The stroke, the overline, and the radicand under them (design spec §6.2).
///
/// Two columns go to the stroke and the space after it, and one row to the overline. An
/// index -- the `3` of a cube root -- is drawn in the row above, right-aligned so that its
/// last column sits over the stroke glyph. Exactly ONE column is free for it: the second
/// stroke column is the gap before the radicand, and an index placed there would read as
/// sitting over the radicand rather than over the root. So an index wider than one column
/// widens the box by the excess, which is what `STROKE - 1` computes.
pub(crate) fn radical(radicand: MathBox, index: Option<MathBox>) -> MathBox {
    const STROKE: u16 = 2;
    let overhang = index
        .as_ref()
        .map_or(0, |b| b.width.saturating_sub(STROKE - 1));
    MathBox {
        width: radicand.width.saturating_add(STROKE).saturating_add(overhang),
        above: radicand.above.saturating_add(1),
        below: radicand.below,
        content: BoxContent::Radical {
            radicand: std::boxed::Box::new(radicand),
            index: index.map(std::boxed::Box::new),
        },
    }
}

/// Delimiters sized to what they enclose (design spec §6.4).
///
/// A one-row body takes the plain characters and no padding — `(x)`, never `╭x╮`, and
/// never `( x )` either, because an inline formula that gained two spaces round every
/// bracket would not read as the author's. A taller body is drawn in box art, and there
/// the padding is not cosmetic: `│1  0│` puts a vertical rule flush against a digit and
/// reads as a table cell.
pub(crate) fn fenced(left: Option<char>, right: Option<char>, body: MathBox) -> MathBox {
    let sides = u16::from(left.is_some()) + u16::from(right.is_some());
    let padding = if body.is_inline() { 0 } else { sides };
    MathBox {
        width: body.width.saturating_add(sides).saturating_add(padding),
```

```rust
// SPDX-License-Identifier: MIT
//! How much room goes between two adjacent pieces of a formula.
//!
//! One table, indexed by the class of the piece on the left and the class of the piece on
//! the right. This shape is a direct answer to stage 1, where the same question was
//! answered by five rules that each read correctly on its own — suppress at the head of a
//! run, suppress after a function name, suppress inside a script — and produced five
//! defects at the joins between them (`-x`, `\sin x`, `2\sin^2 x`, `2{\sin x}^2`,
//! `2{ab}^2`). A table has no joins: every pair is a cell, and a wrong rendering is a
//! wrong cell rather than an interaction nobody enumerated.
//!
//! The owner's ruling, which this table encodes: **one space either side of a relation
//! always; one either side of a binary operator except inside a script operand.** The
//! exception is deliberately *not* in this table — see [`gap`].

/// What a piece of a formula is, for the purpose of what goes beside it.
///
/// These are `pulldown-latex`'s content categories (`Content` at
/// `~/.cargo/registry/src/index.crates.io-*/pulldown-latex-0.8.0/src/event.rs:102`)
/// collapsed to the distinctions that change spacing, plus two of our own: [`Class::Unary`]
/// for a sign with nothing to its left to bind to, and [`Class::Edge`] for the ends of the
/// formula.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum Class {
    /// The start or end of the formula. Nothing is ever inserted against it.
    Edge,
    /// A variable, a number, a symbol: `Content::Ordinary`, `Content::Number`.
    Ordinary,
    /// A function name: `Content::Function`. Parts from its argument.
    Function,
    /// A binary operator with operands either side: `Content::BinaryOp`.
    Binary,
    /// A sign with no left operand — the `-` of `-x`. Binds tight to what follows.
    Unary,
    /// A relation: `Content::Relation`. Always spaced.
    Relation,
    /// A large operator: `Content::LargeOp`.
    Large,
    /// An opening delimiter: `Content::Delimiter { ty: DelimiterType::Open, .. }`.
    Open,
    /// A closing delimiter: `Content::Delimiter { ty: DelimiterType::Close, .. }`.
    Close,
    /// A comma, a full stop, a semicolon: `Content::Punctuation`.
    Punct,
}

impl Class {
    /// Every class, for the totality test.
    pub(crate) const ALL: [Self; 10] = [
        Self::Edge,
        Self::Ordinary,
        Self::Function,
        Self::Binary,
        Self::Unary,
        Self::Relation,
        Self::Large,
        Self::Open,
        Self::Close,
        Self::Punct,
    ];
}

/// Columns to insert between a `left` piece and a `right` piece.
///
/// Always 0 or 1: this is a terminal, and the finer quads TeX sets are not available at
/// cell resolution. Returning a number rather than a `bool` keeps the caller's arithmetic
/// honest — a `Row`'s width is the sum of its parts plus the sum of its gaps.
///
/// **The script-operand exception is not here.** Inside `x^{a+b}` the ruling is that no
/// spaces are set, because the Unicode superscript tables have no raised space and the
/// substitution would decline on it (`src/math/scripts.rs`, the all-or-nothing rule).
/// That is a property of *where the operand is*, known only to the builder, so
/// `build.rs` multiplies this answer by zero rather than passing a flag in here. Two
/// independent decisions; neither can shadow the other, which is exactly what went wrong
/// on the stage-1 branch.
pub(crate) const fn gap(left: Class, right: Class) -> u16 {
    use Class::{Binary, Close, Edge, Function, Large, Open, Ordinary, Punct, Relation, Unary};

    match (left, right) {
        // Nothing borders the ends of the formula.
        (Edge, _) | (_, Edge) => 0,

        // A delimiter hugs its contents on the inside.
        (Open, _) | (_, Close) => 0,

        // A sign with no left operand binds to what follows it.
        (Unary, _) => 0,

        // Punctuation hugs what precedes it and parts from what follows.
        (_, Punct) => 0,
        (Punct, _) => 1,

        // A relation and a binary operator are spaced on both sides.
        (Relation, _) | (_, Relation) | (Binary, _) | (_, Binary) => 1,

        // A function name parts from its argument; a large operator from its operand.
        (Function, _) | (Large, _) | (_, Large) => 1,

        // A number or variable before a function name: `2 sin x`.
        (Ordinary | Close, Function) => 1,

        // Everything else touches: `ab`, `2x`, `x(`, `)y`.
        (Ordinary | Close, Ordinary | Open | Close) => 0,
    }
}
```

```rust
//! `pulldown-latex` events to a box tree.
//!
//! This is the one engine of design spec §4. [`Mode`] is the one flag, and it is consulted
//! only here: a display formula and an inline formula are the same tree, and inline is the
//! constraint `above == 0 && below == 0` over it. A construct that cannot meet the
//! constraint rewrites itself — a fraction becomes `a/b` — or, where no honest one-row
//! form exists, fails with [`MathError::NotInline`] so the caller can show the source.
//!
//! Spacing is not decided here. Every adjacent pair goes through `spacing::gap`, and the
//! one exception the owner ruled — no spaces inside a script operand — is applied by
//! multiplying that answer by zero, because *where an operand sits* is knowledge this file
//! has and the table does not.

use pulldown_latex::event::{Content, DelimiterType, Event};
use pulldown_latex::{Parser, Storage};

use crate::error::MathError;
use crate::math::boxes::{MathBox, row, text};
use crate::math::spacing::{Class, gap};

/// Whether the formula may use more than the row the prose sits on.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum Mode {
    /// One row. A taller construct rewrites itself or fails.
    Inline,
    /// Two dimensions.
    Display,
}

/// Parses `src` into an event stream.
///
/// Lifted from stage 1's `render_inline` unchanged, including why only the first line of
/// the parser's message survives: `ParserError`'s `Display` is four lines — the message,
/// then a `╭─►` box quoting the input — and that box is unreadable in a one-row caption
/// and would put box drawing into `tests/glyph_inventory.rs` that the manual does not
/// claim.
///
/// # Errors
///
/// [`MathError::Parse`] if the LaTeX does not parse.
pub(crate) fn parse(src: &str) -> Result<Vec<Event<'_>>, MathError> {
    let storage = Storage::new();
    // The events borrow from `storage`, so it cannot be a local of this function.
    // `Storage` is an arena; stage 1 held it for the length of one render and so does
    // this. See `mod.rs`, which owns the arena and calls straight through.
    let _ = &storage;
    unreachable!("see Step 3b — `parse` cannot own the arena its output borrows from")
}

/// Turns an event stream into a laid-out box.
///
/// # Errors
///
/// [`MathError::NotInline`] when `mode` is [`Mode::Inline`] and the formula needs a
/// second row.
pub(crate) fn build(events: &[Event<'_>], mode: Mode) -> Result<MathBox, MathError> {
    let (parts, _) = build_run(events, mode, Spacing::Normal)?;
    Ok(parts)
}

/// Whether this run writes the spaces the table asks for.
///
/// The owner's ruling: no spaces inside a script operand, because the Unicode script
/// tables have no raised space and `scripts::substitute` declines on one, which would
/// turn `x^{a+b}` from `xᵃ⁺ᵇ` into the source dump.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
enum Spacing {
    /// The table's answer is used.
    Normal,
    /// Every gap is zero.
    Suppressed,
}

impl Spacing {
    /// The gap actually inserted between two classes under this policy.
    const fn between(self, left: Class, right: Class) -> u16 {
        match self {
            Self::Normal => gap(left, right),
            Self::Suppressed => 0,
        }
    }
}
```

- [ ] **Step 3b: Fix the arena lifetime before going further**

The `parse` signature above **cannot compile**, and this is deliberate — it is the one
place the borrow checker will fight you, and finding it at Step 3b costs minutes where
finding it at Task 12 costs a redesign.

`Parser::new(src, &storage)` yields events that borrow from `storage`
(`$PL/src/parser.rs`), so a function that creates the `Storage` on its stack cannot return
the events. Stage 1 never hit this because `render_inline` parsed *and* consumed the events
in one function body (`src/math/inline.rs:22-41`).

Resolve it by having the caller own the arena:

```rust
/// Parses `src` into an event stream borrowed from `storage`.
///
/// The arena is the caller's because the events borrow from it: `Storage` is
/// `pulldown-latex`'s bump allocator and the `Event`s hold `&'a str` into it.
///
/// # Errors
///
/// [`MathError::Parse`] if the LaTeX does not parse.
pub(crate) fn parse<'a>(
    src: &'a str,
    storage: &'a Storage,
) -> Result<Vec<Event<'a>>, MathError> {
    let mut events = Vec::new();
    for event in Parser::new(src, storage) {
        events.push(event.map_err(|err| MathError::Parse {
            message: err
                .to_string()
```

```rust
/// One horizontal run of events, from `events[0]` until the run's end.
///
/// Returns the box and how many events it consumed, so a caller inside a group knows
/// where to resume.
fn build_run(
    events: &[Event<'_>],
    mode: Mode,
    spacing: Spacing,
) -> Result<(MathBox, usize), MathError> {
    let mut pieces: Vec<(Class, MathBox)> = Vec::new();
    let mut index = 0;
    while index < events.len() {
        match &events[index] {
            Event::End => break,
            Event::Content(content) => {
                pieces.push(atom(content));
                index += 1;
            }
            Event::Begin(grouping) => {
                let (inner, used) = group(events, index, *grouping, mode, spacing)?;
                pieces.push(inner);
                index += used;
            }
            // Tasks 6 to 11 replace each of these in turn. Until then a construct that
            // needs a second row says so by name rather than drawing something wrong.
            Event::Visual(visual) => return Err(MathError::NotInline(visual_name(visual))),
            Event::Script { .. } => return Err(MathError::NotInline("a script")),
            Event::EnvironmentFlow(_) => {
                return Err(MathError::NotInline("a multi-row environment"));
            }
            // `\kern` and friends: a horizontal space we honour as one column, and a
            // vertical one we ignore. Neither can fail.
            Event::Space { width, .. } => {
                if width.is_some() {
                    pieces.push((Class::Ordinary, text(" ")));
                }
                index += 1;
            }
            // Font and style changes carry no cells of their own.
            Event::StateChange(_) => index += 1,
        }
    }
    Ok((assemble(pieces, spacing), index))
}

/// Applies the spacing table to a classified sequence and returns the row.
///
/// The unary pass runs first and separately: a binary operator with nothing to bind to on
/// its left is a sign, and that is a fact about the sequence, not about any one pair.
fn assemble(mut pieces: Vec<(Class, MathBox)>, spacing: Spacing) -> MathBox {
    for i in 0..pieces.len() {
        if pieces[i].0 != Class::Binary {
            continue;
        }
        let left = if i == 0 {
            Class::Edge
        } else {
            pieces[i - 1].0
        };
        if matches!(
            left,
            Class::Edge | Class::Open | Class::Relation | Class::Binary | Class::Punct
        ) {
            pieces[i].0 = Class::Unary;
        }
    }

    let mut parts = Vec::with_capacity(pieces.len() * 2);
    let mut previous = Class::Edge;
    for (class, part) in pieces {
        let columns = spacing.between(previous, class);
        if columns > 0 {
            parts.push(text(" ".repeat(columns as usize)));
        }
        previous = class;
        parts.push(part);
    }
    row(parts)
}
```

```rust
/// One `Content` event as its class and its cells.
///
/// `Content::Relation` is the one payload that is not a `char`: `RelationContent` may hold
/// two characters (`≠` is one, `⩽` another), its field is private, and the only accessor
/// is `encode_utf8_to_buf`. Stage 1 handles it at `src/math/inline.rs:464-470`; this is
/// the same handling in the new shape.
fn atom(content: &Content<'_>) -> (Class, MathBox) {
    match content {
        Content::Text(s) => (Class::Ordinary, text(*s)),
        Content::Number(s) => (Class::Ordinary, text(*s)),
        Content::Function(s) => (Class::Function, text(*s)),
        Content::Ordinary { content, .. } => (Class::Ordinary, text(content.to_string())),
        Content::LargeOp { content, .. } => (Class::Large, text(content.to_string())),
        Content::BinaryOp { content, .. } => (Class::Binary, text(content.to_string())),
        Content::Relation { content, .. } => {
            let mut buf = [0u8; 8];
            let encoded = content.encode_utf8_to_buf(&mut buf);
            // `encode_utf8_to_buf` writes one or two `char`s, so this is valid UTF-8 by
            // construction; the lossy conversion is here because this module may not panic
            // and `from_utf8` returns a Result that has no honest failure branch.
            (
                Class::Relation,
                text(String::from_utf8_lossy(encoded).into_owned()),
            )
        }
        Content::Delimiter { content, ty, .. } => {
            let class = match ty {
                DelimiterType::Open => Class::Open,
                DelimiterType::Close => Class::Close,
                // `\middle|` sits between two operands and reads as a relation does.
                DelimiterType::Fence => Class::Relation,
            };
            (class, text(content.to_string()))
        }
        Content::Punctuation(c) => (Class::Punct, text(c.to_string())),
    }
}
```

```rust
// SPDX-License-Identifier: MIT
//! A box tree onto cells.
//!
//! Two outputs from one tree. [`to_row`] writes the inline form as a single string,
//! because an inline formula is placed as a run of text inside a paragraph and a one-row
//! canvas would gain nothing. [`to_canvas`] draws the display form.
//!
//! Placement is by baseline. Every box knows how many rows it has above and below the row
//! the reader's eye is on, so drawing is one recursive walk carrying an origin: the row
//! the child's baseline lands on, and the column its left edge starts at. Nothing here
//! decides *where on the page* the formula goes — that is design spec §7 and belongs to
//! the renderer, which is the only thing that knows the measure.

use crate::canvas::Canvas;
use crate::error::MathError;
use crate::math::boxes::{BoxContent, MathBox};
use crate::theme::Theme;

/// The inline form: one row of text.
///
/// # Errors
///
/// [`MathError::NotInline`] if the box needs more than the row the prose sits on. The
/// check is here rather than at the call site so the constraint of design spec §4 cannot
/// be forgotten by a future caller.
pub(crate) fn to_row(b: &MathBox) -> Result<String, MathError> {
    if !b.is_inline() {
        return Err(MathError::NotInline("this formula"));
    }
    let mut out = String::new();
    write_flat(b, &mut out);
    Ok(out)
}

/// Appends a zero-height box's cells to `out`.
fn write_flat(b: &MathBox, out: &mut String) {
    match &b.content {
        BoxContent::Text(s) => out.push_str(s),
        BoxContent::Row(parts) => {
            for part in parts {
                write_flat(part, out);
            }
        }
        BoxContent::Fenced { left, right, body } => {
            if let Some(c) = left {
                out.push(*c);
            }
            write_flat(body, out);
            if let Some(c) = right {
                out.push(*c);
            }
        }
        // A zero-height box is a row of text, a list of them, or a one-row fence. Every
        // other variant has a non-zero `above` or `below` by construction (`boxes.rs`),
        // so `is_inline` already rejected it and there is nothing to write here.
        BoxContent::Fraction { .. }
        | BoxContent::Scripts { .. }
        | BoxContent::Limits { .. }
        | BoxContent::Radical { .. } => {}
    }
}
```

- [ ] **Step 4: Write `to_canvas`**

```rust
/// The display form, drawn into a canvas at least `width` columns wide.
///
/// `width` is a floor, not a cap: a formula has exactly one width (design spec §7) and
/// clipping it is the renderer's decision, made where the measure is known. A narrower
/// `width` therefore yields a wider canvas, and the caller compares.
pub(crate) fn to_canvas(b: &MathBox, width: u16, theme: &Theme) -> Canvas {
    let width = width.max(b.width);
    let mut canvas = Canvas::new(width, b.height() as usize, theme.body);
    // The baseline row of the whole formula. Everything below is relative to it.
    place(b, &mut canvas, i32::from(b.above), 0, theme);
    canvas
}

/// Draws `b` with its baseline on `baseline` and its left edge at `col`.
fn place(b: &MathBox, canvas: &mut Canvas, baseline: i32, col: u16, theme: &Theme) {
    match &b.content {
        BoxContent::Text(s) => {
            if let Ok(row) = usize::try_from(baseline) {
                canvas.write_str(row, col as usize, s, theme.body);
            }
        }
        BoxContent::Row(parts) => {
            let mut at = col;
            for part in parts {
                place(part, canvas, baseline, at, theme);
                at = at.saturating_add(part.width);
            }
        }
        BoxContent::Fraction { num, den } => {
            // The rule is the baseline and spans the wider part; each half is centred
            // over or under it.
            if let Ok(row) = usize::try_from(baseline) {
                canvas.hline(row, col as usize, b.width as usize, "─", theme.body);
            }
            place(
                num,
                canvas,
                baseline - i32::from(num.below) - 1,
                col + centre(b.width, num.width),
                theme,
            );
            place(
                den,
                canvas,
                baseline + i32::from(den.above) + 1,
                col + centre(b.width, den.width),
                theme,
            );
        }
        BoxContent::Scripts { base, sub, sup } => {
            place(base, canvas, baseline, col, theme);
            let at = col.saturating_add(base.width);
            if let Some(sup) = sup {
                place(sup, canvas, baseline - i32::from(sup.below) - 1, at, theme);
            }
            if let Some(sub) = sub {
                place(sub, canvas, baseline + i32::from(sub.above) + 1, at, theme);
            }
        }
        BoxContent::Limits { base, under, over } => {
            place(base, canvas, baseline, col + centre(b.width, base.width), theme);
            if let Some(over) = over {
                place(
                    over,
                    canvas,
                    baseline - i32::from(base.above) - i32::from(over.below) - 1,
                    col + centre(b.width, over.width),
                    theme,
                );
            }
            if let Some(under) = under {
                place(
                    under,
                    canvas,
                    baseline + i32::from(base.below) + i32::from(under.above) + 1,
                    col + centre(b.width, under.width),
                    theme,
                );
            }
        }
        // Task 8 and Task 10 fill these in. Drawing nothing is the honest placeholder:
        // the box already reserved the space, so a missing radical shows as a gap rather
        // than as misplaced neighbours.
        BoxContent::Radical { .. } | BoxContent::Fenced { .. } => {}
    }
}

/// The left offset that centres `content` in `field`, rounding left.
///
/// Rounding left rather than right so that a one-column overhang falls on the side the
/// reader's eye starts from, which is the same choice `canvas::align_offset`
/// (`src/canvas/mod.rs:771`) makes for a centred table cell.
const fn centre(field: u16, content: u16) -> u16 {
    field.saturating_sub(content) / 2
}
```

```rust
///
/// The counts are the crate's, documented per variant at `$PL/src/event.rs:157-172`:
/// `SquareRoot` takes one following element, `Root` and `Fraction` take two, and
/// `Negation` applies to the next event whatever it is.
fn visual_box(
    events: &[Event<'_>],
    at: usize,
    visual: Visual,
    mode: Mode,
    spacing: Spacing,
) -> Result<(MathBox, usize), MathError> {
    match visual {
        Visual::Fraction(_) => {
            let (num, a) = element(events, at + 1, mode, spacing)?;
            let (den, b) = element(events, at + 1 + a, mode, spacing)?;

                Mode::Display => boxes::fraction(num, den),

                // decides its spacing exactly as it would for any other operator, rather
                // than this arm inventing a second answer.
                Mode::Inline => boxes::row(vec![num, boxes::text("/"), den]),
            };

        }
        Visual::SquareRoot => {
            let (radicand, a) = element(events, at + 1, mode, spacing)?;
            let boxed = match mode {
                Mode::Display => boxes::radical(radicand, None),
                Mode::Inline => boxes::row(vec![boxes::text("√"), radicand]),
            };

        }

            let (index, b) = element(events, at + 1 + a, mode, spacing)?;

                // Declining shows the source instead, which is design spec §9's whole
                // point: a formula in the wrong place, not an error.
                Mode::Inline => Err(MathError::NotInline("a root with an index")),
            }
        }
        Visual::Negation => {

            // (`$PL/src/event.rs:166-171`) and this is what a terminal can do.
```

```rust
/// A base and its scripts.
///
/// `ScriptPosition::Movable` is the crate's "above and below by preference, to the right
/// when inline" (`$PL/src/event.rs:193-201`), so [`Mode`] resolves it. This is the third
/// and last place in this file that reads the flag.
fn script_box(
    events: &[Event<'_>],
    at: usize,
    ty: ScriptType,
    position: ScriptPosition,
    mode: Mode,
    spacing: Spacing,
) -> Result<(MathBox, usize), MathError> {
    let (base, a) = element(events, at + 1, mode, spacing)?;
    // Operands of a script are built with spacing suppressed: there is no raised space in
    // Unicode, so `scripts::superscript` declines on one and `x^{a+b}` would fall back to
    // its source. The owner ruled this exception; it lives here rather than in the table
    // because it is a fact about position, not about a pair.
    let operand_spacing = match mode {
        Mode::Inline => Spacing::Suppressed,
        Mode::Display => spacing,
    };
    let (sub, sup, used) = match ty {
        ScriptType::Subscript => {
            let (s, b) = element(events, at + 1 + a, mode, operand_spacing)?;
            (Some(s), None, 1 + a + b)
        }
        ScriptType::Superscript => {
            let (s, b) = element(events, at + 1 + a, mode, operand_spacing)?;
            (None, Some(s), 1 + a + b)
        }
        ScriptType::SubSuperscript => {
            let (lo, b) = element(events, at + 1 + a, mode, operand_spacing)?;
            let (hi, c) = element(events, at + 1 + a + b, mode, operand_spacing)?;
            (Some(lo), Some(hi), 1 + a + b + c)
        }
    };

    let stacked = matches!(position, ScriptPosition::AboveBelow)
        || (matches!(position, ScriptPosition::Movable) && matches!(mode, Mode::Display));

    let boxed = match (mode, stacked) {
        (Mode::Display, true) => boxes::limits(base, sub, sup),
        (Mode::Display, false) => boxes::scripts(base, sub, sup),
        (Mode::Inline, _) => {
            // All-or-nothing per group: substitute both or neither. A partial
            // substitution renders `a_{bc}` as `a_b c`, a different expression.
            let mut out = draw::to_row(&base)?;
            if let Some(sub) = &sub {
                let cells = draw::to_row(sub)?;
                out.push_str(&scripts::subscript(&cells).ok_or(MathError::NotInline(
                    "a subscript with no lowered form",
                ))?);
            }
            if let Some(sup) = &sup {
                let cells = draw::to_row(sup)?;
                out.push_str(&scripts::superscript(&cells).ok_or(MathError::NotInline(
                    "a superscript with no raised form",
                ))?);
            }
            boxes::text(out)
        }
    };
    Ok((boxed, used))
}

/// One element: a single event, or a whole `Begin…End` group.
///
/// "Element" is the crate's own word for what a `Visual` or `Script` governs, and its
/// counts are given per variant. A group counts as one.
fn element(
    events: &[Event<'_>],
    at: usize,
    mode: Mode,
    spacing: Spacing,
) -> Result<(MathBox, usize), MathError> {
    match events.get(at) {
        None => Err(MathError::NotInline("an unfinished construct")),
        Some(Event::Begin(_)) => {
            let (b, used) = build_run(&events[at + 1..], mode, spacing)?;
            // +1 for the Begin, +1 for the End that stopped the run.
            Ok((b, used + 2))
        }
        Some(_) => {
            let (b, used) = build_run(&events[at..=at], mode, spacing)?;
            Ok((b, used))
        }
    }
}
```

### Task 8: Tall delimiters

Spec §6.4. `\left…\right` sizes to what it encloses, in box drawing, with light arcs for
round parentheses. The one-row case takes the plain character.

**Files:**
- Create: `src/math/delim.rs`
- Modify: `src/math/build.rs` (the `Grouping::LeftRight` arm), `src/math/draw.rs` (the

**Interfaces:**
- Produces: `pub(crate) fn pieces(delimiter: char, side: Side, height: u16) -> Vec<&'static str>`
  — the glyph for each row, top to bottom. `Side::{Left, Right}`.

**The trap this task exists to not fall into.** Stage 1's plan asserted, citing nothing,
that `\left…\right` *"draws its delimiters as ordinary `Content`"*. It does not: they are
fields of the `Grouping::LeftRight(Option<char>, Option<char>)` variant
(`$PL/src/event.rs:315`). Ignoring the `Begin` therefore rendered
`\left(\frac{a}{b}\right)^2` as `a/b²` — **wrong mathematics, silently**. `None` is a real
`\left.`: an intentionally invisible delimiter, not a missing one, and nothing is drawn
for it. Stage 1's fixed handling is at `src/math/inline.rs:334-355`.

**Decision — the glyph table, and why box drawing.** Spec §6.4 rules the Unicode
bracket-piece block (U+239B–U+23AD) out for font coverage: box drawing is what the frames,
tables and quote bars already draw with, so it inherits coverage that is already proven on
the reader's terminal. Light arcs stand in for round parentheses.

| delimiter | top | middle | bottom |
|---|---|---|---|
| `(` | `╭` | `│` | `╰` |
| `)` | `╮` | `│` | `╯` |
| `[` | `┌` | `│` | `└` |
| `]` | `┐` | `│` | `┘` |
| `{` | `╭` | `┤` | `╰` |
| `}` | `╮` | `├` | `╯` |
| `\|` | `│` | `│` | `│` |
| anything else | the character itself on every row | | |

A brace's middle is the `┤`/`├` of spec §6.4's `cases` illustration. The fallback row —
the character repeated — is what keeps this total: `⟨`, `⌈` and `‖` all reach it, and
repeating the author's own character is honest where inventing box art would not be.

```rust
// SPDX-License-Identifier: MIT
//! Delimiters sized to what they enclose (design spec §6.4).
//!
//! Box drawing, not the Unicode bracket-piece block (U+239B–U+23AD). The block is the one
//! designed for the job and it is thinner on the ground in terminal fonts than box drawing
//! is; these are the characters the frames, tables and quote bars already draw with, so
//! they inherit coverage that is already proven on the reader's terminal.
//!
//! A one-row body takes the plain character: `(x)`, never `╭x╮`.

/// Which end of the enclosure a delimiter is.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub(crate) enum Side {
    /// The opening delimiter.
    Left,
    /// The closing delimiter.
    Right,
}

/// The glyph for each row of `delimiter` at `height`, top to bottom.
///
/// A delimiter with no box-art form repeats itself. That is honest where inventing a
/// shape would not be: `⟨` drawn as a made-up stack of pieces is a character the reader
/// has never seen standing for one they have.
pub(crate) fn pieces(delimiter: char, side: Side, height: u16) -> Vec<&'static str> {
    let height = usize::from(height.max(1));
    let plain = char_str(delimiter);
    if height == 1 {
        return vec![plain];
    }
    let Some((top, middle, bottom)) = art(delimiter, side) else {
        return vec![plain; height];
    };
    let mut out = Vec::with_capacity(height);
    out.push(top);
    out.extend(std::iter::repeat_n(middle, height - 2));
    out.push(bottom);
    out
}

/// The three pieces of a growable delimiter, or `None` for one with no box-art form.
const fn art(delimiter: char, side: Side) -> Option<(&'static str, &'static str, &'static str)> {
    match (delimiter, side) {
        ('(', _) => Some(("╭", "│", "╰")),
        (')', _) => Some(("╮", "│", "╯")),
        ('[', _) => Some(("┌", "│", "└")),
        (']', _) => Some(("┐", "│", "┘")),
        // The middle piece is the one design spec §6.4's `cases` illustration draws.
        ('{', _) => Some(("╭", "┤", "╰")),
        ('}', _) => Some(("╮", "├", "╯")),
        ('|', _) => Some(("│", "│", "│")),
        _ => None,
    }
}

/// The delimiter as a one-column string.
///
/// A lookup rather than an allocation: `pieces` returns `&'static str` so the caller can
/// write it straight into a canvas, and every delimiter a reader will meet is here.
const fn char_str(delimiter: char) -> &'static str {
    match delimiter {
        '(' => "(",
        ')' => ")",
        '[' => "[",
        ']' => "]",
        '{' => "{",
        '}' => "}",
        '|' => "|",
        '⟨' => "⟨",
        '⟩' => "⟩",
        '⌈' => "⌈",
        '⌉' => "⌉",
        '⌊' => "⌊",
        '⌋' => "⌋",
        '‖' => "‖",
        '/' => "/",
        '\\' => "\\",
        _ => "│",
    }
}
```

reader is not told about. If review prefers, the alternative is to widen `char_str` into a

```rust
/// Draws `src` as a block of box art at least `width` columns wide.
///
/// Design spec §6. The canvas is exactly `width` columns on every row, or wider if the
/// formula is — a formula has one width and this function does not choose it.
///
/// A formula that draws no cells returns an empty canvas rather than an error: design
/// spec §16.3 makes a definition-only block contribute no rows, and stating the rule over
/// the *result* is what keeps `\newcommand`, `\def`, a comment and whitespace behaving
/// alike with no list to maintain.
///
/// # Errors
///
/// [`MathError::Parse`] if the LaTeX does not parse. [`MathError::TooWide`] if it draws
/// wider than `width`, carrying the width it needs.
pub fn render_display(src: &str, width: u16, theme: &Theme) -> Result<Canvas, MathError> {
    let storage = Storage::new();
    let events = build::parse(src, &storage)?;
    let laid_out = build::build(&events, build::Mode::Display)?;
    if laid_out.is_empty() {
        return Ok(Canvas::empty(width));
    }
    if laid_out.width > width {
        return Err(MathError::TooWide {
            needed: laid_out.width,
        });
    }
    Ok(draw::to_canvas(&laid_out, width, theme))
}
```

```rust
// SPDX-License-Identifier: MIT
//! Placing a display formula: centred if it fits, side-scrolled if it does not.
//!
//! The counterpart to [`super::diagram`], and deliberately the same shape so that
//! `document.rs` places both the same way. One difference, and it is a simplification:
//! **a formula has exactly one width.** A diagram can be re-laid out narrower, so
//! `diagram` searches for the narrowest width that works and spends a probe budget doing
//! it. This module measures once. `Limits::probes` is therefore ignored here, and that is
//! deliberate rather than an oversight — the type is shared so the pager's ceiling stays
//! in one place.
//!
//! Centring is design spec §7, and it is the only centring in this program. It applies
//! only when the formula fits: a formula wider than the measure is left-aligned at its
//! natural width, because centring something that is about to be side-scrolled would put
//! its left edge off screen before the reader had seen it.

use crate::canvas::Canvas;
use crate::doc::{Node, NodeKind};
use crate::theme::Theme;

use super::diagram::Limits;
use super::{Ctx, RenderOptions, bridge, code};

/// The formula this block draws, and the width it needed.
///
/// `None` when the node is not display math, when the formula fails for any reason other
/// than being too wide, and when its width is past `limits`. In each of those cases the
/// caller renders the block normally, which produces the centred formula or the framed
/// source.
pub(crate) fn formula(
    node: &Node,
    from: u16,
    limits: Limits,
    theme: &Theme,
    options: &RenderOptions,
) -> Option<(u16, Canvas)> {
    let NodeKind::Math {
        literal,
        display: true,
    } = &node.kind
    else {
        return None;
    };
    let source = literal.trim_matches('\n');
    // Measured once. The error carries the answer, not a hint to search from.
    let needed = match bridge::math_display(source, from, theme) {
        Ok(_) => return None, // It fits; the ordinary block path centres it.
        Err(crate::error::MathError::TooWide { needed }) => needed,
        Err(_) => return None, // Any other failure keeps dumping source at this width.
    };
    if needed > limits.width() {
        return None;
    }
    let canvas = bridge::math_display(source, needed, theme).ok()?;
    let ctx = Ctx::new(theme, options);
    Some((needed, code::math_block(canvas, needed, source, node.source, ctx)))
}
```

```rust
/// Places a drawn formula in a block, with the one span and one atom of design spec §10.
///
/// Not [`diagram_block`], which rebases each label's span onto its own bytes. A formula
/// has no labels and no per-cell provenance to rebase: `pulldown-latex`'s events carry no
/// source positions at all, which is *why* §10 makes a formula atomic rather than a
/// consequence of it. Passing an empty `origins` to `diagram_block` would behave the
/// same and say nothing.
pub(crate) fn math_block(
    mut canvas: Canvas,
    width: u16,
    literal: &str,
    block: SourceSpan,
    ctx: Ctx<'_>,
) -> Canvas {
    if let Some((row, rows, col, cols)) = drawn_bounds(&canvas) {
        canvas.add_span(SearchSpan {
            source_start: block.start,
            source_end: block.end,
            unit: None,
            row,
            col,
            cols,
            // The cells say `a/b` where the bytes say `\frac{a}{b}`. A span that is not a
            // byte-for-byte copy has no interior position, so search and selection take
            // all of it or none of it.
            copied: false,
        });
        canvas.add_atom(Atom {
            row,
            rows,
            col,
            cols,
            source_start: block.start,
            source_end: block.end,
            content: literal.to_string(),
        });
    }
    canvas.resize_width(width, ctx.base);
    canvas
}
```

Spec §16. **A macro defined anywhere in the document is visible to every formula after
it.** Not TeX's rule, not GitHub's, and deliberate: GitHub shipped cross-block
`\newcommand` and withdrew it, so no document can depend on it, and the only documents this
changes are the ones that define a macro once at the top — which go from broken to working.

**Files:**
- Modify: `src/doc/mod.rs`, `src/doc/convert.rs`, `src/render/bridge.rs`,
  `src/render/block.rs`, `src/render/inline.rs`
- Test: `src/doc/tests.rs`, `src/render/tests.rs`

**Interfaces:**
- Produces: `Doc::math_preamble(&self, before: usize) -> &str` — the definitions from every
  math node whose source starts before byte `before`, concatenated in document order.

**How, and why not through the crate's API.** `MacroContext` is private in
`pulldown-latex` and is rebuilt per `Parser`, so macros cannot be carried across formulas
through it. They do not need to be: collect the definitions in document order and **prepend
them as a preamble to each later formula's source**. One owned `String` per formula, no
upstream change.

**The ordering rule is one pass in document order**, which gives "visible after the
defining formula, not before" for free. **A definition that appears after its use is not
found, and that is not a bug to be fixed by a second pass** — it is the rule a reader can
predict without knowing how the document is walked.

**Decision — collect by scanning the literal for `\newcommand` and `\def`, and keep the
whole formula's source when either appears.** The alternative, extracting just the
definition, means parsing LaTeX's argument syntax ourselves — brace counting, optional
arguments, `\def`'s parameter text — which is a second front end and this project has one
rule about that. Prepending the whole literal is safe because a definition-only block draws
nothing anyway (spec §16.3) and a mixed block's visible part is drawn where it stands and
re-drawn invisibly as part of the preamble, costing one extra parse.

**Flag at review:** that re-parse means a document with a hundred formulas after a mixed
definition block parses that block a hundred times. If a profile shows it, the fix is to
cache the preamble string per node index, not to write an argument parser.

```rust
/// The macro definitions visible to a formula starting at byte `before`.
///
/// Design spec §16. `pulldown-latex`'s `MacroContext` is private and is rebuilt per
/// `Parser`, so macros cannot be carried between formulas through its API. They do not
/// need to be: the definitions are prepended to the later formula's source as a preamble.
///
/// Document order, and strictly before: a definition that appears after its use is not
/// found. That is the rule stated in the spec rather than a limitation of one pass, and
/// it is the rule a reader can predict without knowing how the document is walked.
pub fn math_preamble(&self, before: usize) -> String {
    self.math_definitions
        .iter()
        .take_while(|(at, _)| *at < before)
        .map(|(_, src)| src.as_str())
        .collect::<Vec<_>>()
        .join("\n")
}
```
